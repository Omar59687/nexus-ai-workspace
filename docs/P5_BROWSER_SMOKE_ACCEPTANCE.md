# Phase 5 — Reproducible Chromium acceptance (synthetic only)

The new dedicated workflow `.github/workflows/p5-review-browser-smoke.yml`
launches **real headless Chromium** against an actual loopback FastAPI
server. This is separate from the existing PostgreSQL and Phase 4 quality
workflow; both are required to pass for the current feature branch.

The temporary server uses a deliberately fake, in-memory financial-review
ledger, a noncustomer PDF generated by pypdf, and an artificial in-process
test token. It never reads a real annual report, contacts an external API,
opens network ports beyond localhost, or persists credentials.

The browser tests exercise:

- Access denied without the synthetic token
- The opt-in reviewer page and successful request flow
- In-memory token entry and immediate clearing of the password field
- Pending queue selection and escaped indexed evidence text
- Original PDF download with the exact expected bytes
- Approval withheld until both explicit visual-attestation boxes are checked
- Authorized approval/rejection and queue refresh
- Clearing the browser session after use

Run locally only with suitable development dependencies and a Chromium
installation:

```shell
python -m pip install 'pytest>=8,<9' 'playwright>=1.55,<2' 'uvicorn>=0.30,<1' 'fastapi>=0.115,<1' 'pypdf>=6,<8' 'pydantic>=2,<3' 'pandas>=2.2,<3' 'openpyxl>=3.1,<4'
python -m playwright install chromium
python -m pytest -v tests/test_financial_review_browser.py
```

This acceptance test closes the **synthetic real-browser smoke** gap when
green. It does **not** satisfy the 21 real PostgreSQL tests skipped in an
environment without the guarded database DSN, or the real-report acceptance
gate, or an actual human looking at financial rows. Continue to report these
as independent gates. The standard Phase 5 GitHub Actions workflow already
tests PostgreSQL against an isolated disposable service. Do not interpret
the Playwright mock ledger as database persistence verification.


## Reviewed analytics and session switching

The reviewer workbench now offers a separate **Reviewed financial analysis**
form. It submits explicit company, metric, currency, unit and bounded years
to the existing permission-gated `POST /financial-reviews/analyze` endpoint
and displays exact Decimal *strings* with year-over-year values and source
document/page citations. The UI never derives financial labels or recomputes
totals on the client. An unapproved or ambiguous series must be rejected by
the server. Source and provenance data are inserted with DOM `textContent`,
not interpreted as HTML.

Real Chromium coverage checks the resulting amount and provenance after
a synthetic approval. It also checks switching from a valid session to an
invalid one clears the previous queue, excerpt and reviewed analysis.
Asynchronous HTTP responses carry a browser-session generation check so
a response from a prior token is rejected after disconnect or token switch.
This does not replace server-side access controls; it prevents stale data
from being reinserted into an already cleared page.

The reviewed analysis output remains a backend assertion tied to explicit
human decisions; synthetic UI tests do not establish financial accuracy in
a real report.
